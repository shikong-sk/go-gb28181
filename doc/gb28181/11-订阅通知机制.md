# GB/T 28181-2016 订阅通知机制

## 概述

GB/T 28181 基于 IETF RFC 3265 定义了订阅通知机制，用于目录变化、报警事件等信息的实时推送。

## 基本流程

### 订阅流程

```
订阅者                              通知者
  │                                   │
  │ ──── SUBSCRIBE ─────────────────>│ (1)
  │      Event: xxx                   │
  │      Expires: 时间                │
  │                                   │
  │ <─── 200 OK ──────────────────── │ (2)
  │      Expires: 时间                │
  │                                   │
  │ <─── NOTIFY ──────────────────── │ (3)
  │      Subscription-State: active   │
  │                                   │
  │ ──── 200 OK ─────────────────────>│ (4)
  │                                   │
  │ <─── NOTIFY ──────────────────── │ (5)
  │      事件数据                      │
  │                                   │
  │ ──── 200 OK ─────────────────────>│ (6)
  │                                   │
  │ ──── SUBSCRIBE ─────────────────>│ (7)
  │      Expires: 0 (取消订阅)        │
  │                                   │
  │ <─── 200 OK ──────────────────── │ (8)
```

## SUBSCRIBE消息

### 消息格式

```sip
SUBSCRIBE sip:3402000000@192.168.1.200:5060 SIP/2.0
Via: SIP/2.0/UDP 192.168.1.100:5060;rport;branch=z9hG4bK-xxx
From: <sip:34020000002000000001@3402000000>;tag=BK32B1U8DKDrB
To: <sip:3402000000@3402000000>
Call-ID: 17250@192.168.1.100
CSeq: 1 SUBSCRIBE
Contact: <sip:192.168.1.100:5060>
Event: presence
Expires: 90
Content-Type: Application/MANSCDP+xml
Max-Forwards: 70
Content-Length: xxx

[查询内容]
```

### 重要头域

| 头域 | 说明 |
|------|------|
| Event | 事件类型 |
| Expires | 订阅有效期（秒） |
| Subscription-State | 订阅状态（响应中） |

## NOTIFY消息

### 消息格式

```sip
NOTIFY sip:34020000002000000001@192.168.1.100:5060 SIP/2.0
Via: SIP/2.0/UDP 192.168.1.200:5060;rport;branch=z9hG4bK-xxx
From: <sip:3402000000@3402000000>;tag=BK32B1U8DKDrB
To: <sip:34020000002000000001@3402000000>
Call-ID: 17250@192.168.1.100
CSeq: 1 NOTIFY
Contact: <sip:192.168.1.200:5060>
Event: presence
Subscription-State: active;expires=90;retry-after=0
Content-Type: Application/MANSCDP+xml
Max-Forwards: 70
Content-Length: xxx

[通知内容]
```

### Subscription-State

| 状态 | 说明 |
|------|------|
| active | 订阅激活 |
| pending | 订阅等待 |
| terminated | 订阅终止 |

### 终止原因

| 原因 | 说明 |
|------|------|
| timeout | 订阅超时 |
| giveup | 无法建立订阅 |
| rejected | 订阅被拒绝 |

## 目录订阅

### 订阅请求

```xml
<?xml version="1.0"?>
<Query>
  <CmdType>Catalog</CmdType>
  <SN>17430</SN>
  <DeviceID>34020000001110000001</DeviceID>
</Query>
```

### 事件订阅头域

```
Event: Catalog;id=1894
```

### 目录变化通知

```xml
<?xml version="1.0"?>
<Notify>
  <CmdType>Catalog</CmdType>
  <SN>162</SN>
  <DeviceID>34020000001110000001</DeviceID>
  <SumNum>2</SumNum>
  <DeviceList Num="2">
    <Item>
      <DeviceID>34020000001320000004</DeviceID>
      <Event>OFF</Event>
    </Item>
    <Item>
      <DeviceID>34020000001320000005</DeviceID>
      <Event>ADD</Event>
      <Name>新设备</Name>
      <Status>ON</Status>
    </Item>
  </DeviceList>
</Notify>
```

### Event状态

| 值 | 说明 |
|----|------|
| ON | 上线 |
| OFF | 下线 |
| VLOST | 视频丢失 |
| DEFECT | 故障 |
| ADD | 新增设备 |
| DEL | 删除设备 |
| UPDATE | 更新信息 |

## 报警订阅

### 订阅请求

```xml
<?xml version="1.0"?>
<Query>
  <CmdType>Alarm</CmdType>
  <SN>17430</SN>
  <DeviceID>34020000001340000001</DeviceID>
  <StartAlarmPriority>1</StartAlarmPriority>
  <EndAlarmPriority>4</EndAlarmPriority>
  <AlarmMethod>0</AlarmMethod>
  <StartTime>2010-11-11T00:00:00</StartTime>
  <EndTime>2010-12-11T00:00:00</EndTime>
</Query>
```

### 订阅参数

| 参数 | 说明 |
|------|------|
| StartAlarmPriority | 起始报警级别 |
| EndAlarmPriority | 结束报警级别 |
| AlarmMethod | 报警方法（0=全部） |
| StartTime | 开始时间 |
| EndTime | 结束时间 |

### 报警通知

```xml
<?xml version="1.0"?>
<Notify>
  <CmdType>Alarm</CmdType>
  <SN>1</SN>
  <DeviceID>34020000001340000001</DeviceID>
  <AlarmPriority>4</AlarmPriority>
  <AlarmMethod>2</AlarmMethod>
  <AlarmTime>2009-12-04T16:23:32</AlarmTime>
  <AlarmDescription>设备故障</AlarmDescription>
  <Longitude>171.3</Longitude>
  <Latitude>34.2</Latitude>
</Notify>
```

## 移动设备位置订阅


```xml
<?xml version="1.0"?>

  <Longitude>171.3</Longitude>
  <Latitude>34.2</Latitude>
  <Speed>60</Speed>
  <Direction>90</Direction>
```

### 位置参数

| 参数 | 说明 |
|------|------|

| Latitude | 纬度 |
| Speed | 速度（km/h） |
| Direction | 方向（0-360度） |
| Altitude | 海拔（米） |
| Interval | 上报间隔（秒） |

## 订阅刷新

### 刷新请求

在订阅即将过期前发送新的SUBSCRIBE请求：

```sip
SUBSCRIBE sip:3402000000@192.168.1.200:5060 SIP/2.0
Via: SIP/2.0/UDP 192.168.1.100:5060;rport;branch=z9hG4bK-xxx
From: <sip:34020000002000000001@3402000000>;tag=BK32B1U8DKDrB
To: <sip:3402000000@3402000000>;tag=xxx
Call-ID: 17250@192.168.1.100
CSeq: 2 SUBSCRIBE
Event: Catalog;id=1894
Expires: 600
Content-Type: Application/MANSCDP+xml

[查询内容]
```

## 取消订阅

### 取消请求

发送Expires为0的SUBSCRIBE请求：

```sip
SUBSCRIBE sip:3402000000@192.168.1.200:5060 SIP/2.0
Via: SIP/2.0/UDP 192.168.1.100:5060;rport;branch=z9hG4bK-xxx
From: <sip:34020000002000000001@3402000000>;tag=BK32B1U8DKDrB
To: <sip:3402000000@3402000000>;tag=xxx
Call-ID: 17250@192.168.1.100
CSeq: 3 SUBSCRIBE
Event: Catalog;id=1894
Expires: 0
Content-Length: 0
```

### 终止通知

通知者发送终止状态：

```sip
NOTIFY sip:34020000002000000001@192.168.1.100:5060 SIP/2.0
Subscription-State: terminated;reason=timeout
```

## Event头域格式

### 格式定义

```
Event: 事件类型[;id=标识符]
```

### 常用事件类型

| 类型 | 说明 |
|------|------|
| presence | 在线状态 |
| Catalog | 目录变化 |
| Alarm | 报警事件 |
| MobilePosition | 移动位置 |

### id参数

用于区分同类型的多个订阅：

```
Event: Catalog;id=1894
```

## 订阅状态管理

### 状态转换

```
    ┌──────────┐
    │  初始    │
    └────┬─────┘
         │ SUBSCRIBE
         ▼
    ┌──────────┐
    │ pending  │
    └────┬─────┘
         │ NOTIFY
         ▼
    ┌──────────┐
    │  active  │◄────────┐
    └────┬─────┘         │
         │ SUBSCRIBE    │ 刷新
         │ (refresh)    │
         │              │
         ▼              │
    ┌──────────┐        │
    │terminated│────────┘
    └──────────┘
```

### 有效期管理

- 默认订阅有效期：600秒
- 建议刷新时间：有效期的一半
- 过期后自动终止

## 注意事项

1. **Call-ID一致性**
   - 同一订阅会话使用相同Call-ID
   - 刷新时From/To的tag应保持一致

2. **Event参数**
   - Event头域必须与订阅请求一致
   - id参数用于区分同类订阅

3. **订阅刷新**
   - 在Expires到期前刷新
   - 建议在有效期50%时刷新

4. **错误处理**
   - 订阅失败返回错误响应
   - 通知失败需要重试

5. **通知确认**
   - 每个NOTIFY需要200 OK确认
   - 未确认需要重发
