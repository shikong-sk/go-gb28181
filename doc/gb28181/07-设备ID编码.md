# GB/T 28181-2016 设备ID编码

## 编码概述

GB/T 28181 设备ID采用统一编码规则，确保系统内设备唯一标识。

## 编码类型

### A类编码（20位）

用于设备、系统、平台等实体的标识。

```
第1-8位：行政区划代码
第9-10位：行业编码
第11-13位：类型编码
第14-20位：设备序号
```

**行业编码（第9-10位）**:

| 17-20 | 预留 |

### B类编码（18位）

用于业务分组、虚拟组织等。

```
第1-8位：行政区划代码
第9-13位：类型代码
第14-18位：序号
```

## 行政区划代码

按 GB/T 2260-2007 规定，8位行政区划代码：

| 位数 | 说明 |
|------|------|
| 1-2 | 省级代码 |
| 3-4 | 市级代码 |
| 5-6 | 区县级代码 |
| 7-8 | 乡镇级代码（默认00） |

**示例**:
- 34020000：安徽省芜湖市
- 11000000：北京市

## 设备序号

设备序号用于在同一行政区划、同一类型内的设备区分。

- 范围：0000001-9999999
- 编码原则：先注册先编码

## 编码规则

### 中心信令控制服务器

```
区划代码 + 200 + 序号
示例：34020000200000000001
```

### SIP设备（DVR）

```
区划代码 + 111-130 + 序号
示例：34020000111000000001
```

### 网络摄像机(IPC)

```
区划代码 + 134 + 序号
示例：34020000134000000001
```

### 通道编码

```
区划代码 + 类型 + 序号
示例：34020000132000000001（摄像机通道）
```

### 业务分组

```
区划代码 + 400 + 序号
示例：34020000400000000001
```

### 虚拟组织

```
区划代码 + 300 + 序号
示例：34020000300000000001
```

## 层级关系

### 设备目录树

```
根节点（行政区划）
├── 平台/系统
│   ├── 中心信令控制服务器
│   ├── 媒体服务器
│   └── 报警服务器
├── 设备
│   ├── DVR
│   │   ├── 通道1
│   │   └── 通道2
│   └── IPC
├── 业务分组
│   └── 分组1
└── 虚拟组织
    └── 组织1
```

### ParentID规则

- 子设备的ParentID为父设备ID
- 根节点ParentID为行政区划或为空
- 支持多级嵌套

## 编码验证

### 正则表达式

```
// 20位设备ID
^(\d{2}|\d{4}|\d{6}|\d{8}|\d{20})$

// 18位编码
^(\d{2}|\d{4}|\d{6}|\d{8}|\d{18})$
```

### 长度验证

| 类型 | 有效长度 |
|------|----------|
| 行政区划 | 2, 4, 6, 8位 |
| A类编码 | 20位 |
| B类编码 | 18位 |

## 注意事项

1. **唯一性保证**
   - 同一系统内设备ID必须唯一
   - 建议采用统一分配机制

2. **行政区划代码**
   - 必须使用GB/T 2260标准代码
   - 不存在的级别用00填充

3. **设备序号**
   - 从0000001开始编码
   - 不能以0开头

4. **类型代码扩展**
   - 131-199、600-999保留给其他设备
   - 新增设备类型应预留编码空间

5. **通道编码**
   - 通道ID独立于设备ID
   - 通过ParentID关联所属设备
